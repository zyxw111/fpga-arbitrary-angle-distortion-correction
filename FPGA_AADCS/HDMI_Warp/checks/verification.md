# HDMI 工程验证记录（2026-10-22）

目标器件 PG2L100H-6IFBG484，HDMIK V1.1。工程从本地 `zyxw` 的 `5843c0d`
复制所需 DDR、PCIe、FIFO、传输模块后独立扩展，原工程未修改。
MS7200 控制表来自用户提供的 `RK3568_HDMI_IN` 配套例程；总线引擎增加开漏、
ACK 检查及 LUT/地址流水级的触发等待。只初始化 HDMI RX，不使用 MS7210 TX。

## RTL 回归

四组测试全部通过，详细记录见 `rtl-summary.json` 和各测试的 `.txt` 输出。

| 测试 | 验证内容 |
|---|---|
| hdmi_map | 300 组逆仿射和 Brown 映射，与独立浮点公式比较，误差不超过 1/16 像素；含非等焦距、负坐标和五个畸变系数 |
| hdmi_stream | RGB888→RGB565 打包，正/负 VS 极性，完整帧边界检查，短行和 FIFO 溢出拒收 |
| hdmi_init | 线级 I²C 从机解码 0x56/0x57、16 位寄存器地址、读回及 ACK；逐笔比对 308 次写入，覆盖频率状态变化及 NACK 错误 |
| hdmi_pcie | 输入 DDR→逆仿射/Brown→四邻域 DDR 读取/缓存→RGB565 双线性插值→输出 DDR→校验→真实 PCIe RX/MMIO/CplD/TX RTL |

端到端使用 64×64 输入、64×40 输出，12° 旋转，k1=-0.16、k2=0.04、k3=-0.01、
p1=0.002、p2=-0.003。三帧共 7,680 像素全部与整数参考结果一致；
34 个描述符、132 个 MWr TLP，含不同长度/4 KiB 边界、TX 停顿、主机空闲期间快照保持。
两帧高度错误的输入被丢弃；CAM2 寄存器、大小、校验值、帧数和 0x7200 标识通过真实完成包读取。

DDR 使用带独立读写停顿、同周期首返回及范围检查的接口模型；PCIe PHY/块 RAM 使用模型。
这验证逻辑与协议，不代表板间信号、电气时序或真实驱动 DMA 可见性已上板验证。

## 完整尺寸软件参考

`tools/preview.py` 验证 640×480 输入、640×400 输出：

- 默认配置逐像素等于输入第 40～439 行，坐标误差 0。
- 演示配置最大坐标误差约 **0.041628 像素**；与 OpenCV 浮点映射相比，BGR 通道平均差约
  0.368，p99 为 6（RGB565 通道取整及 OpenCV 插值权重量化也贡献差异）。
- ARM 预览脚本读取完整 512,000 字节 RGB565 小端文件并成功输出 PNG。

`preview/` 图片均为**软件参考**，不是板卡截图，也不是物理镜头的标定验证。
默认参数为便于联调的原图居中裁剪；演示参数用于展示变换，不是实际标定参数。

## PDS 构建与交付

最终源码通过 PDS 全流程，结果及源文件/位流 SHA-256 见 `manifest.json`；
`timing.rtr` 保存完整多角时序报告，`build-output.txt` 保存构建日志。
交付的默认位流使用 `config/warp.json`，而非演示参数。生成目录包含工具的临时 PDS，
请仅打开源码入口 `HDMI_Warp/hdmi_warp.pds`。自动审批策略拦截了临时文件删除，故构建目录保留。

本工程为单帧快照及串行像素处理实现，不承诺 30 fps，不包含 1080p30 优化。
本次没有重新下载 FPGA，也没有连接真实 HDMI 输入或 ARM 验证实际显示。
ARM 桌面预览还需要板端已有 numpy 和带 GUI 的 OpenCV，板端环境未改动。
