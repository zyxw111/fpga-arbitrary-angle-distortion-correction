# PCIe FPGA 参考核查与双帧所有权（2026-10-17）

## 参考边界

只参考 `fpga-arbitrary-angle-distortion-correction-zyxw` 的 FPGA 部分；其中 ARM 代码、接收程序和历史主机测试均不作为我们实际 ARM 工程的接口依据。实际 ARM 工程尚未提供。不覆盖参考工程或原 `prj/Distortion_re`。

参考包含 PG2L100H / FBG484 / -6 的 `aadcs_pcie_top`、本地 Gen1 x2 PCIe IP、DMA RTL、约束、仿真与位流。保存的时序报告满足约束；这是参考构建的证据，不是本项目的时序结论。参考数据源为按需生成的 640×400 图案，不含 DDR3、摄像头或校正，其帧率由读请求节拍决定。

参考值得保留的检查点：背压下禁止源前进；用当前命令而非滞后长度检查 4 KiB 越界；仅在真实 RX 载荷上写 BAR；高地址写脉冲自清零；独立时钟上电复位和各域同步释放。正式采用 IP 前仍须逐项对照和仿真，不直接替换原 DMA。

## 新增 frame.v

两个 DDR 帧槽，各自经历 FREE→WRITE→FULL→READ→FREE。`wr_start && wr_ready` 申请 `wr_slot`；写入端必须等所有 DDR 写事务真正完成，再以 `wr_finish` 提交。`wr_good=0` 丢弃不完整帧并复用本槽；成功提交时锁存 `wr_id`。

`rd_valid && rd_start` 取得完整帧 `rd_slot/rd_id`。消费者持有帧直至 `rd_finish`。释放必须发生在全部 DMA 源读取完成、没有在途 DDR 读再访问本槽之后；不能以 split.done（仅命令被接收）、描述符提交或首个读请求作为释放依据。主机缓冲区是否可复用还需独立的真实完成协议。

生产/消费各自按槽0、槽1循环，保证提交顺序。两槽占用时停止分配；实时源不能等待时，应丢弃整帧并在下一个帧首重试，不允许覆写已占用槽。错误 finish 锁存 error，复位清除；复位前外部必须先停止/清空在途 DDR/DMA 事务。

控制全部位于 DDR 用户时钟域；像素域和 PCIe 域必须通过握手或异步 FIFO 传递控制。不得直接跨域连接。模块不含 DDR 数据存储、地址生成、像素计数、完整性验证、CDC 或主机缓冲分配。

## 验证与后续

`tb_frame.sv` 检查坏帧丢弃、槽占用保护、两帧排队、读取暂停、不同槽同时提交/释放、连续轮换、帧号和非法释放/复位。该验证仅为所有权单元仿真；尚未加入 PDS 顶层。
