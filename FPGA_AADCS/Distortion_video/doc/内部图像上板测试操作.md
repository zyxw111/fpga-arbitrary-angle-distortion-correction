# 不接摄像头上板测试

目标板：RK3568_MES2L100H，FPGA 为 PG2L100H-6IFBG484。无需连接摄像头或转接板。显示器接 **RK3568 的 HDMI OUT**，FPGA 经 PCIe 将图像送到 ARM。

本版流程：内部图像生成 → RGB565 打包 → FPGA DDR3 写入 → 全帧读回校验 → 完整 DMA 段预取 → PCIe → ARM 整帧比较 → 保存并显示实抓图片。初始化后图像存为静态帧，后续可以反复传输，用来检查后半段链路和校正效果。

## 1. 选择下载文件

使用本文件同目录 `bitstreams` 中的文件；文件哈希与构建结果见 `验收清单.json`。

| 文件 | 用途 | 预期图像 |
|---|---|---|
| board_bars.sbit | 第一组：先验证通路 | 彩条，下方带渐变 |
| board_raw.sbit | 第二组：畸变输入 | 弯曲的测试网格 |
| board_corrected.sbit | 第二组：校正输出 | 经过现有校正 RTL 后的网格 |

建议按表格顺序测试。三份程序共用真实 DDR3、PCIe 和 ARM 抓图通路。原始与校正图使用同一个合成镜头模型；真实摄像头标定参数以后另行接入。

通过 PDS 的 Fabric Configuration 工具连接开发板 JTAG，扫描器件并核对 PG2L100H，添加所选 `.sbit`，先下载到 FPGA SRAM。首次测试先不固化 QSPI Flash。板卡断电后 SRAM 程序会丢失；换图案需要重新下载对应文件。

## 2. 在 ARM 上运行

将本目录完整复制到 RK3568，例如 `/home/rock/board_demo`。必须保留 `expected` 下的三个参考文件，它们来自已经逐像素核验的 RTL 输出。

先关闭原有采集程序，避免两个程序同时控制 PCIe/DMA。下载 FPGA 后检查：

```sh
lspci -nn
ls -l /dev/pcie_dma_memcpy
```

应找到 `0755:0755` 的 FPGA 设备。默认地址是 `0002:21:00.0`，以实际 `lspci` 和 `/sys/bus/pci/devices` 为准。若加载 SRAM 后旧设备状态失效，应在停止所有采集程序后重新枚举对应端点；不要随意移除 PCIe 根桥。若系统启动时根控制器因没有链路而未注册，单纯 rescan 可能无效，需要按照该系统的 PCIe 控制器启动流程恢复。

然后执行：

```sh
cd /home/rock/board_demo
sudo sh run_board_test.sh 0002:21:00.0 3
```

工具在板上使用 `cc` 编译，默认验证连续 3 帧；无需交叉编译器。板上需要现有 `/dev/pcie_dma_memcpy` 分配服务。该服务的匹配内核源码目前未提供，本包不替换系统内核驱动。

成功时每帧输出 `PASS frame ... 512000 bytes exact`，最后输出 `PASS board capture.`，并生成对应的 `captured_bars.ppm`、`captured_raw.ppm` 或 `captured_corrected.ppm`。这些文件是实际 DMA 收到的数据，不是复制参考图片。

如果系统有 GTK3 开发环境，脚本还会编译显示工具。在桌面会话中打开：

```sh
./board_view captured_corrected.ppm
```

没有 GTK3 开发环境时，抓图验证仍可完成，把 PPM 拷回电脑查看即可。SSH 无图形桌面时不会自动弹窗。

## 3. 判定与故障信息

- J16 指示灯亮：PCIe 链路建立；M17 常亮：DDR 内部图像核验通过。M17 闪烁表示检测到错误，具体以 ARM 读取的错误码为准。
- `Wrong bitstream`：当前仍是旧程序、选错端点或 BAR 不可读。
- `DDR/image not ready`：检查板型、时钟、DDR 初始化和错误码。
- `DMA completion timeout/error`：描述符未完成，不要继续启动另一个采集进程。停止操作并重置 FPGA/恢复 PCIe，必要时重启系统后重新下载 SRAM 程序。
- `Payload mismatch/stale DMA mapping`：实际数据与参考不符，也可能是运行内核的 DMA 映射不具备所需一致性。不能据此认定“只是显示问题”。程序会失败，不会把参考图当成实抓图输出。
- 非法/未对齐 DMA 分配地址会被拒绝，不会拿这个地址启动 FPGA 写内存。

程序先等待 FPGA 的最终 PCIe 写包被 IP 接收，再等待 CPU 实际看到正确数据；两者独立检查。完成计数本身不等于 Linux DMA 缓存维护。发生传输超时时不会主动调用 SHUTDOWN 释放可能仍在被写入的缓冲区，恢复后应重启清理。

## 4. 修改代码和重新构建

仅在独立副本开发：

`E:/pango/Project_2022.2/Distortion/prj/Distortion_video`

打开 `checks/board_bars/board_bars.pds`、`checks/board_raw/board_raw.pds` 或 `checks/board_corrected/board_corrected.pds`。对应顶层在 `source/rtl/board_bars.v`、`board_raw.v`、`board_corrected.v`；顶部 `DEMO_GROUP=0/1`、`DEMO_VIEW=0/1` 选择彩条、畸变原图或校正图。修改后必须重建，现有 `.sbit` 不会自动变化。

主 `Distortion_re.pds` 保留之前的仿真诊断顶层 vtop，**不是本次板级下载入口**。不要使用原工程 `prj/Distortion_re`。

本次板级顶层使用 **R4/T4 的板载 125MHz 差分时钟**，SSTL15D_I，先生成 25MHz，再提供给演示逻辑及 DDR 参考输入；PCIe 使用 F6/E6 独立参考时钟。V4 未进入本次顶层。DDR 与 PCIe 保持各自原生用户时钟，通过同步器和完整段缓冲跨域。

## 5. 本次验证的边界

软件/RTL 测试与 PDS 构建结果见验收清单。尚未在你的实板执行烧录、抓帧或电压测量，因此不能把离线 PASS 当作实板 PASS。

这一版验证的是 640×400 RGB565 的内部静态图像、实际校正算法、DDR 顺序读写、PCIe 分段传输和 ARM 完整比对。它不等于连续实时摄像头、1080p60、真实摄像头 DDR 随机读取缓存、运行时镜头参数控制或长期硬件稳定性全部完成。先把本包三种模式的日志和实抓图跑通，后续再接真实视频源。
