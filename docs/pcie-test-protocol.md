# PCIe 测试数据接口 v0.1

适用工程：`FPGA_AADCS` 的 `aadcs_pcie_top`，目标 PG2L100H-6IFBG484。
方向是 FPGA Endpoint 向 RK3568 Root Complex 的 DMA Memory Write。
配置基线为 Gen1 x2、ID `0755:0755`、最大 TLP payload 128 字节。

## 主机可见资源

参考 IP 保持 BAR0=8KiB、BAR1=4KiB、BAR2=8KiB；本阶段发送控制使用 BAR1。
BAR0/BAR2 保留参考 DMA 存储，不是 640x400 完整视频帧缓存。
主机不能把 BAR 地址或用户态虚拟地址用作 DMA 目标，必须从匹配的驱动获得总线地址。

| BAR1 字节偏移 | 写入内容 |
| --- | --- |
| 0x110 | 主机 DMA 总线地址低 32 bit |
| 0x120 | 主机 DMA 总线地址高 32 bit |
| 0x100 | 命令：bit24=1（FPGA写主机）；bit16=0/1（32/64bit地址）；bit9:0=dwords-1 |

三个寄存器均使用完整 32-bit 写。低地址和必要的高地址必须先于命令写入。
参考读路径未提供可靠完成状态，不应靠读取这些地址判断 DMA 完成。

本阶段数据源的传输约束：

- 目标地址 16 字节对齐，长度为 16 字节的整数倍。
- 一条描述符 16~4096 字节，不能跨越 4KiB 边界；大传输由主机拆分。
- 4096 字节对应命令 `0x010003FF`（32-bit 目标地址）。
- 1280 字节对应命令 `0x0100013F`，遇到页边界仍需拆成两条。
- 分割不会重置数据源位置；源在下一次同步读取时继续输出。
- 主机串行发描述符，留出完成时间；没有命令队列、完成中断或帧所有权握手。

参考 DMA 通用逻辑还能表达其他长度，本阶段只验证上述数据源约束。
不能将未验证的非 16-byte 长度、主机主动切换模式或多进程访问作为支持能力。

## 彩条和计数模式

KEY1 释放：640x400 RGB565 彩条，像素字节交换，帧首具有 16 字节状态头。
KEY1 按住：连续 uint32 计数，无帧头。切换前停止主机采集。
KEY0 复位端点和源；可能需要主机重新枚举。

数据源是按请求运行的虚拟流。它没有真实摄像头帧时钟，帧率由主机请求节拍决定。
测试图可用于验证数据正确性和显示链路，不能代表真实视频采集的时延或帧率。

## 后续图像链路接口

`o_dma_write_data_req` 是一次已经接受的读请求，`i_dma_write_data` 提供一拍同步读延迟的
128-bit 数据。后续视频缓存接口需要满足同样的延迟和供数条件，或修改 DMA 适配层。
本阶段接口没有数据源 `valid/ready`，因此不能把可能欠载的摄像头 FIFO 直接连接上去。
接入真实视频时还需设计帧所有权、供数节拍、CDC、错误状态及可靠的完成机制。
