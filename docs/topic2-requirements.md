# 选题二：工程要求与当前差距

依据用户提供的《2026 FPGA 赛道选题指南－紫光同创》PDF 第 12–14 页
（正文页码 10–12），题目为“基于紫光同创 FPGA 的任意角度的畸变矫正”。
本文件记录实现范围和证据，不能将仿真、综合或内部测试图案视为整机实测。

| 赛题要求 | 当前基线状态 | 完整工程必须补齐 |
| --- | --- | --- |
| 实时采集、缓存、显示 | 静态内部图案、DDR 校验、PCIe 发送 | 真实视频输入、连续帧缓存、ARM 接收显示闭环 |
| 二阶径向与切向畸变 | coord 包含 k1/k2/p1/p2 运算 | 从真实标定结果加载参数，按帧原子更新 |
| 双线性重采样 | bilin 已验证；演示通过 chart 按地址计算像素 | 从真实 DDR 帧读取四邻域，缓存和调度必须满足带宽 |
| 动态任意角度/仿射 | 当前位流没有仿射功能 | 上位机角度指令、逆仿射、与镜头模型组合、跨时钟参数提交 |
| 实时性能和资源 | 640×400 静态演示；旧版完整时序通过 | 连续输入下的 1080p 性能、延迟、丢帧和资源实测 |
| 自适应增强（高阶） | 未接入 | 确定高阶范围后加入 Gamma 或直方图增强 |
| 质量和文档 | RTL 单元与合成图参考 | 真实标定、网格直线度、MTF50/SFR、端到端延迟报告 |

原基线的“矫正图”使用真实坐标与插值 RTL，但四邻域像素由合成图案函数提供，
不能证明真实摄像头的随机 DDR 帧取样已实现。KEY1 的三模式选择也不等于角度矫正。

赛题明确要求使用真实相机标定数据，不能用演示的 k1=-0.25 作为实物验收数据。
现有 ARM 三个厂家示例没有匹配当前统一位流的视频接收程序。

## 输入方案与性能约束

完整工程的顶层和存储架构依赖真实输入选择，尚待用户确定：

- ARM 采集 USB/V4L2 视频，经 PCIe 输入 FPGA，矫正后返回 ARM 的 HDMI 显示。
- 摄像头直连 FPGA：需要型号、接口、连接器引脚和有效电平资料。
- HDMI 直连 FPGA：需要扩展模块的收发芯片、接口和引脚资料。

ARM 采集方案可复用现有板卡接口，无需新增 FPGA 摄像头引脚；仍需实现主机到 FPGA 的图像输入方向。
RGB565 的 1920×1080@30 原始图像单向负载为 124,416,000 字节/秒，
60 fps 为 248,832,000 字节/秒。ARM 往返方案需分别满足两个方向的负载，
另加协议、显示转换、DDR 四邻域访问等开销；不能用静态图重复读取帧率作为真实处理帧率。

在输入方案确定前，不猜测摄像头引脚、HDMI 控制器或板上电平。
保持一个板级 PDS 入口；开发中间工程不加入源目录。

## 已开始的独立开发

新增 `source/rtl/affine_coord.v`：输出坐标到输入坐标的 2×3 逆仿射核心，
矩阵为有符号 Q16.16，输出为有符号 Q20.12，三拍延迟，每拍一个坐标。
支持负坐标和小数偏移，溢出输出饱和值及标志。
`sim/tb_affine.sv` 使用独立有理数参考向量，覆盖任意角度、连续输入、valid 空拍、舍入、溢出和复位。

该核心目前独立验证，尚未接入 `boardtop` 或既有位流；不能据此声称任意角度整机工程已完成。
输入链路及目标范围确定后，继续完成帧存储/重采样、参数寄存器、ARM 程序和整机验证。
